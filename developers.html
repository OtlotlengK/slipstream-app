API Reference

REST API

All authenticated API requests use a ValoraTap API key in the Bearer Authorization header. Keep keys on your server. The browser and mobile app must never receive a secret API key.

POST/functions/v1/transactions

Create a transaction

Creates a verified transaction record in Production or an isolated simulated transaction in Sandbox.

Headers

AuthorizationBearer API key
Content-Typeapplication/json
Idempotency-KeyRequired, max 128 chars

Body

amount — positive number, max 999999999.99
currency — three-letter ISO currency code; must match the merchant currency
payment_method — cash, eft, card, or online
customer.name — required, 1–160 characters
customer.email — optional
customer.phone — optional
description — required, max 2000 characters
reference — optional, max 200 characters

Node.js

const response = await fetch(
  'https://pddjualtnhgmplampucn.supabase.co/functions/v1/transactions',
  {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${process.env.VALORATAP_API_KEY}`,
      'Content-Type': 'application/json',
      'Idempotency-Key': 'order_12345'
    },
    body: JSON.stringify({
      amount: 1250.00,
      currency: 'ZAR',
      payment_method: 'card',
      customer: { name: 'John Doe' },
      description: 'Towing service',
      reference: 'ORDER-12345'
    })
  }
);

const data = await response.json();
if (!response.ok) throw new Error(data.error);
console.log(data);
POST/functions/v1/transaction-events

Append a Proof Chain event

Production endpoint for recording validated transaction lifecycle events against a receipt.

receipt_id — required UUID
event_type — CUSTOMER_ACKNOWLEDGED, PAYMENT_CONFIRMED, DELIVERY_CONFIRMED, FULFILMENT_CONFIRMED, WARRANTY_ACTIVATED, RETURN_REQUESTED, or REFUND_COMPLETED
actor_type — system, merchant, customer, or api
actor_name — optional, max 120 chars
metadata — optional JSON object, max 8 KB
Sandbox note: transaction-events currently accepts Production keys only. Use Sandbox transactions and webhooks to validate an integration before enabling live Proof Chain writes.
curl https://pddjualtnhgmplampucn.supabase.co/functions/v1/transaction-events \
  -X POST \
  -H "Authorization: Bearer vt_live_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "receipt_id": "RECEIPT_UUID",
    "event_type": "DELIVERY_CONFIRMED",
    "actor_type": "api",
    "actor_name": "My App",
    "metadata": {"order_id": "12345"}

POST/functions/v1/verify

Verify a receipt

Checks a receipt belonging to the authenticated merchant. Production only.

Send either receipt_id or verification_hash.
Permissions: verification:read.
A successful response contains verified: true and the receipt's amount, currency, payment method, description, verification hash, status and timestamps.
curl https://pddjualtnhgmplampucn.supabase.co/functions/v1/verify \
  -X POST \
  -H "Authorization: Bearer vt_live_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"verification_hash":"YOUR_HASH"}'
Webhooks

Receive signed events

Create a Sandbox or Production endpoint in Developer Console → Webhooks. ValoraTap sends HTTPS POST requests and signs the exact body you receive.

Headers

X-ValoraTap-Event

Event type, such as transaction.created.

X-ValoraTap-Delivery

Unique delivery ID.

X-ValoraTap-Signature

Format: t=TIMESTAMP,v1=HMAC_SHA256.

Signature verification

Compute HMAC-SHA256 over timestamp + "." + raw_request_body using your webhook signing secret. Compare the result to v1 using a constant-time comparison. Do not parse and re-serialize JSON before hashing.

Node.js
import crypto from 'node:crypto';

export function verifyValoraTapWebhook(rawBody, signatureHeader, secret) {
  const parts = Object.fromEntries(
    signatureHeader.split(',').map(part => part.split('='))
  );
  const signed = `${parts.t}.${rawBody}`;
  const expected = crypto
    .createHmac('sha256', secret)
    .update(signed, 'utf8')
    .digest('hex');

  return crypto.timingSafeEqual(
    Buffer.from(expected),
    Buffer.from(parts.v1 || '')
  );
}
Python
import hashlib
import hmac

def verify_valoratap_webhook(raw_body, signature, secret):
    parts = dict(item.split("=", 1) for item in signature.split(","))
    signed = f"{parts['t']}.{raw_body}".encode()
    expected = hmac.new(
        secret.encode(), signed, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected, parts.get("v1", ""))
Webhook delivery behaviour: ValoraTap records each delivery, retries unsuccessful deliveries, and exposes delivery history in Developer Console. Return a 2xx response after successful signature validation and processing. Make your handler idempotent using X-ValoraTap-Delivery.
Errors

Predictable failures

HTTPCodeMeaning
400invalid_json / invalid_amount / invalid_currency / invalid_payment_method / …The request is malformed or a field failed validation.
401missing_api_key / invalid_api_keyAuthentication failed.
403insufficient_permissionsThe key is valid but does not have the required permission.
404receipt_not_foundThe requested receipt does not exist for the authenticated merchant.
409idempotency_key_reused / currency_mismatchThe request conflicts with an existing operation or merchant configuration.
413request_too_large / metadata_too_largeThe request exceeded the endpoint size limit.
429rate_limit_exceededRate limit reached. Respect the Retry-After header.
500*_error / server_configuration_errorValoraTap could not complete the operation. Retry safely where applicable.
Retry rule: retry network failures and 5xx responses with the same Idempotency-Key. Do not generate a new idempotency key for the same logical transaction.
