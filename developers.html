Quickstart

Three steps to connect.

01

Create an API key

Open your ValoraTap dashboard, generate a key and store the secret securely on your server.

Open dashboard →
02

Send a transaction

After your payment provider confirms a payment, POST the transaction to the ValoraTap endpoint.

See endpoint →
03

Use the receipt

Save the returned receipt ID and verification URL in your system and send the receipt to the customer.

See response →
Security rule: never put a live API key in frontend JavaScript, mobile app code or public GitHub repositories. Call ValoraTap from your server/backend.

Transactions API

Create a transaction.

Use this endpoint when your business system has a transaction that should become a ValoraTap receipt.

Request
POST https://pddjualtnhgmplampucn.supabase.co/functions/v1/transactions
Authorization: Bearer sk_live_xxxxxxxxx
Content-Type: application/json
Idempotency-Key: order_2026_00124

{
  "amount": 1250.00,
  "currency": "ZAR",
  "payment_method": "card",
  "customer": {
    "name": "John Doe",
    "email": "john@example.com",
    "phone": "+27820000000"
  },
  "description": "Towing service",
  "reference": "MOS-2026-00124"
}
Success response
{
  "success": true,
  "receipt_id": "uuid",
  "receipt_no": "VT-000124",
  "verification_url": "https://.../verify.html?id=uuid",
  "verification_hash": "sha256..."
}

Idempotency

Send a unique Idempotency-Key for every logical transaction. Retrying the same key is safe; ValoraTap will not create a duplicate transaction.

Parameters

What you can send.

FieldTypeRequiredDescription
amountnumberYesPositive transaction amount in ZAR.
currencystringYesCurrently supported value: ZAR.
payment_methodstringYesPayment method used by the customer.
customerobjectNoName, email and phone where available.
descriptionstringNoWhat the customer paid for.
referencestringNoYour own order, booking or transaction reference.

Transaction events

Build a complete Proof Chain.

After a receipt exists, your integration can record lifecycle events such as payment confirmation, delivery confirmation, customer acknowledgement, warranty activation, returns and refunds.

PAYMENT_CONFIRMED

Payment provider confirms the transaction.

DELIVERY_CONFIRMED

Business records completion or delivery.

CUSTOMER_ACKNOWLEDGED

Customer acknowledges the transaction.

WARRANTY_ACTIVATED

Warranty or after-sales coverage begins.

RETURN_REQUESTED

Customer requests a return.

REFUND_COMPLETED

Refund is completed and recorded.
